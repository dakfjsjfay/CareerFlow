## 2. 开发方式：纵向切片（二轮审查确定）

**原则：按业务功能切片，每个切片内前后端同周期开发、每天联调。禁止前端做完所有页面、后端做完所有接口后再集中联调。**

切片顺序（与优先级一致）：登录 → 对话建档 → 简历生成 → 导出 → 岗位匹配 → 反向优化 → 投递 → 提醒和反馈。

每个切片结束即达到该切片验收标准（见 acceptance.md §5），验收通过才进入下一切片。

**每日协作机制**：晨会 10~15 分钟定当日切片任务 → 白天独立开发 → 下午 Apifox 联调接口 → 晚上合并 dev + 解决冲突 → 复盘记录。

**Claude Code 使用纪律**（全体）：不让 Claude 一次性生成整个项目；每个任务走「分析→计划→风险→分步开发→测试→人工检查提交」流程；完成后人工确认功能正常再合并。

## 8. 答辩预案（评委可能的问题）

- **Q：和普通 AI 简历生成器有什么区别？**
  A：普通工具只解决「制作」；我们覆盖「对话收集→结构化档案→简历生成→JD 匹配→差距反向优化→投递状态跟踪→主动提醒→反馈回流」完整求职闭环。系统发现差距后通过多轮对话引导补充**真实**经历，简历版本与投递反馈全程留痕，让优化有据可依。
- **Q：怎么证明 AI 没有编造经历？**
  A：证据链机制——每条经历保存用户原始表述、来源与确认状态，未确认信息只存在于证据表、绝不进入档案；简历只使用已确认且可追溯的信息；演示防幻觉测试用例。
- **Q：匹配分数怎么算的？**
  A：Java 加权公式 M=Σwᵢsᵢ/Σwᵢ，逐技能展示证据与状态，分数完全可解释；不是大模型拍脑袋的百分比。
- **Q：反馈如何优化匹配？**
  A：如实说明——可解释规则权重（不感兴趣的岗位类型后置 + 历史已读率/面试率统计微调），不宣称训练出了推荐算法。
- **Q：导出为什么必须指定版本？**
  A：投递记录关联具体简历版本，导出指定版本保证「投递时用的简历」与「导出的简历」一致，版本管理才有意义。
