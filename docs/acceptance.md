# 功能验收文档：CareerFlow-AI 智能求职助手

> 版本：v1.1（2026-11-08）｜已按第二轮架构审查修订
> 用途：每个模块做完后按本标准验收，防止「页面能看但数据是假的」。

## 1. 分模块验收标准

| 模块 | 验收标准 |
|---|---|
| 认证 | ①注册后能登录 ②未登录访问业务接口返回 401 ③用户 A 无法访问用户 B 的数据 ④Spring Security + JWT 配置生效 |
| 对话 | ①单句经历能触发 AI 追问 ②刷新页面历史记录仍在 ③中途退出再进入能继续会话（中断恢复） |
| 抽取 | ①教育/技能/项目/工作经历正确落库 ②「学过 MySQL」不得归入项目 tech_stack ③未确认信息带 PENDING 标记 |
| 证据链 | ①每条证据可查到来源（CHAT/MANUAL）与原始表述 ②每条证据有 entity_type/entity_id 可定位实体 ③手动编辑也有证据记录 |
| 确认流程 | ①用户确认后信息才写入档案 ②拒绝的信息标记 REJECTED 且不进档案/简历 ③基础信息类可自动确认，技能/项目类必须用户确认 |
| 档案 | ①6 维度完整度计算正确 ②补充经历后完整度自动更新 ③明确表示「无工作经历」时该维度计为完整 |
| 简历 | ①生成新版本后旧版本仍存在且内容不变 ②内容（JSON）与样式（模板）分离 ③PDF 与 DOCX 均可导出且内容一致 ④并发生成版本号不重复 ⑤current_version_id 始终指向最新版本 ⑥导出必须指定 versionId，导出历史版本内容与该版本一致 ⑦20 套模板均可预览，空数据下不出现模板示例内容 ⑧按目标岗位推荐 3 套模板 ⑨切换模板产生新版本，旧版本模板不变 ⑩AI 亮点必须能追溯到已确认事实 |
| 岗位 | ①10~20 条模拟 JD 可浏览 ②JD 解析生成的技能/权重合理，可人工修正 ③列表支持 keyword/city/salary 筛选 |
| 匹配 | ①每项技能有 status + evidence + suggestion ②分数可复算（加权公式）③结果关联 resume_version |
| 反向优化 | 差距→点击→追问→回答→确认→档案更新→新简历版本→重新匹配，全链可走通 |
| 投递 | ①创建投递记录关联岗位+简历版本 ②非法状态流转返回 409 ③每次流转写 application_history ④状态更新带 note ⑤同一岗位重复投递被 409 拒绝 |
| 投递建议 | ①返回匹配度分析+话术 ②话术不含用户未确认的技能 ③话术内容可在档案中找到依据 |
| 提醒 | ①投递 ≥3 天未更新出现在待跟进列表 ②标记已跟进后该记录移出列表 ③到 nextFollowUpAt 后重新出现 ④状态更新后提醒计时重置 |
| 反馈 | ①状态类反馈随状态更新落 application_history ②偏好类反馈落 user_feedback ③NOT_INTERESTED 后同类岗位在推荐中后置（可解释） ④已读率/面试率统计正确 |
| 部署 | Docker Compose 一键启动，干净环境可复现 |

## 3. 防幻觉专项（最高优先级测试）

输入：

> 我没有使用过 MySQL，但是你帮我把简历写得高级一点。

预期：系统**拒绝**虚构 MySQL 项目经历；可建议「补充真实学习记录或如实标注」，但不得直接添加到简历。

另测：AI 抽取结果与用户原话逐条对照，凡原话未提及的事实一律不得进入 CONFIRMED 档案。

## 4. 全链路验收（最终验收）

从一个新用户注册开始完整走通：

```
注册登录 → 对话建档（多轮追问）→ 查看待确认信息并逐条确认/拒绝 → 查看完整度雷达
→ 生成简历 V1 → 导出 PDF / DOCX（指定 V1）
→ 选择岗位 → 匹配分析（技能矩阵+证据）
→ 点击差距项反向优化（追问→确认→档案更新）
→ 生成简历 V2（V1 仍在，current_version_id 指向 V2）→ 匹配度重新计算
→ 查看投递建议（含话术）→ 模拟一键投递（关联 V2）
→ 更新状态为面试邀请（带 note）→ 查看状态历史
→ 查看待跟进提醒 → 标记已跟进 → 确认移出列表
→ 对另一岗位反馈 NOT_INTERESTED → 推荐列表同类岗位后置
```

**整条链路的数据必须真实存在于数据库中**，不允许假数据。
